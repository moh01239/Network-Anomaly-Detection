## 📖 Introduction: Challenges in Network Security
Threats to networks can be divided into two main categories:
* **Known Threats:** These attacks focus on known security vulnerabilities (e.g., DDoS, DoS, and phishing).
* **Unknown Threats:** These are less predictable and do not follow expected patterns (e.g., sudden spikes in traffic and unauthorized access).

### The Importance of Machine Learning
We can improve anomaly detection through machine learning (ML). By detecting and handling abnormal behaviors autonomously, even in the absence of training data, we can continuously adapt to evolving patterns, enabling us to identify new attacks as they occur.

The **k-Means algorithm** is one of the most popular algorithms due to its simplicity, efficiency, and scalability. It also reduces manual monitoring to automatically identify unusual activity in network traffic.

---

## ⚙️ Methodology
1. **Gathering and Preparing Data:** First, we collect network traffic data and then clean and normalize the features to calculate the required distance.
2. **Feature Engineering:** Here, we add some features to help us distinguish between abnormal and normal behavior, such as protocols and packet rates, to increase the effectiveness of anomaly detection.
3. **Using the k-Means Algorithm & Choosing k:**
   * **k-Means Steps:** Select the number of clusters (k) ➔ Initialize centroids randomly ➔ Assign each data point to the nearest center of gravity (Euclidean distance) ➔ Update the weight points based on the elements in the cluster ➔ Repeat until centroids converge.
   * **Choosing the optimal k (Elbow Method):** Test different k values. Calculate the within-cluster mean sum of squares (WCSS) for each k. Plotting WCSS versus k, the point where the curve bends (the "elbow") indicates the optimal k. This provides the best balance between model accuracy and simplicity.
4. **Identification of Anomalies:** We calculate the distance of each point from the center of gravity in a group, then we classify the points that are more than 10% farther from the center of gravity as anomalies. The thresholds are tuned to balance precision (fewer false alarms) and recall (detecting more real attacks).
5. **Evaluation Metrics:** Accuracy, Precision, Recall, F1-Score, and Confusion Matrix.
6. **Comparison with Traditional Methods:** Traditional methods are good for weak attacks, but they are also vulnerable to new attacks and techniques. k-Means learns from patterns to detect new attacks, such as zero-day attacks, without the need for pre-existing signatures and rules.

---

## 📊 Results and Analysis (Real Example)
The values below are taken from an actual experiment on the **NSL-KDD dataset**, and demonstrate the model's performance on the Train, Validation, and Test21 sets.

We observe average to poor recall performance across all three sets, and it is an indication that k-means failed to identify a large proportion of true incidents. For example, the recall value on the Train set is only ≈15.5%, resulting in a low F1 value of ≈25.6% even though the precision appears to be relatively higher on some sets.

* **What does "Precision ≈ 82%" mean?**
  It means that out of every 100 alerts generated by the model, approximately 82 were true attacks and 18 were false alarms. That means there are a large number of true alerts relative to the total number of alerts.
* **What does "Recall ≈ 31.5%" mean?**
  It means that out of every 100 true attacks that occurred in the data, the model only detected approximately 31 of them—that is, it missed ~69 attacks out of every 100.

> **💡 The Security Guard Analogy:**
> The model "prefers" to issue alarms when it is certain (hence, high precision), but the cost of this certainty is that it becomes very reluctant to issue alarms in other cases, missing many attacks. Imagine a security guard who only raises an alarm when he is 100% certain—there will be fewer false alarms, but many small thefts will go undetected.

### Why does this happen?
* **The threshold setting is too high:** This makes the model rigid and only issues an alert when there is near certainty.
* **Data imbalance:** The number of "normal" cases is much greater than the number of attacks, making it difficult for the model to learn all types of attacks.
* **Clustering limits:** The value of k or the clustering method are not suitable for the diversity of attacks (some types of attacks do not appear as clear patterns in the clusters).

### What can we do practically to improve performance?
* Lower the threshold slightly to increase recall (while monitoring for an increase in false alarms).
* Increase examples of rare attack types or use data balance (oversampling or collecting more data).
* Try alternative algorithms or different k-value settings and observe how the Precision vs. Recall balance changes.

---

## 🎯 Conclusion
The research confirms the importance of employing ML techniques to new challenges in network security. The k-Means algorithm can cluster network behavior and detect some anomalies that may indicate malicious activity.

However, its ability to detect all types of attacks remains limited. The results indicate that the model achieved relatively high precision with poor recall. That means it identified a portion of the attacks, but omitted a large number of actual attacks. This highlights the sensitivity of the model to settings such as threshold percentages and the number of clusters (k).

Despite this limitation, the k-Means algorithm remains useful for unsupervised anomaly detection for its simplicity, speed, and scalability. It represents a good starting point for developing intelligent intrusion detection systems. To improve detection accuracy, future studies should be conducted to combine k-Means with other machine learning models (such as SVM algorithms) or deep learning techniques.
